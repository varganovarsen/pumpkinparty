# Решения по ходу работы

Мелкие детали, которых нет в спеке (SPEC 0). Заказчик просматривает.

## Этап 1 (ядро)

1. **Вход и загрузка фото через REST, остальное через WebSocket.** Загрузка файлов по WS неудобна; `join`/`claim` идут через `POST`, чтобы получить токен до открытия WS. Все прочие изменения — команды по WS.
2. **Фото-профиль: обрезка на телефоне, обработка на сервере.** Телефон отправляет оригинал, сервер делает HEIC→JPEG и EXIF-поворот и отдаёт превью; на превью гость двигает и масштабирует круг; сервер режет PNG 256×256 с прозрачными углами. Фильтры и наклейки для профиля подключатся вместе с редактором селфи (модуль 03), в спеке они «опционально».
3. **Профиль ведущего:** создаётся по ссылке «Создать мой профиль игрока» на `/host` (открывает `/?as_host=1`). Ведущий может быть только один. `in_scoring` ведущего = `host_in_scoring`; менять нельзя после флага `quiz_started` (выставит модуль 02).
4. **«Это я?»** — по имени без учёта регистра, только если у игрока нет ни одного живого подключения.
5. **Живые фазы** (подтверждение при выходе): вопрос и вердикты квиза, отсчёт и игра, открытое голосование.
6. **«Следующий шаг»** = следующая сцена по рекомендуемому порядку (SPEC 8): ambient → квиз → перерыв → игра → аллея → итоги резьбы → рейтинг → финальное фото → слайд-шоу → скачивание. Модули будут подставлять контекстные шаги (например «Показать вопрос»).
7. **Заглушки ассетов.** Эталоны лежат в `server/stubs/` (генерирует `tools/make_stubs.py`, нужен ffmpeg). Сервер при старте копирует заглушку на место отсутствующего файла в `assets/`. Файл считается заглушкой, пока его хэш совпадает с эталоном, — замена файлом с тем же именем работает без правок кода. Наклейки-заглушки называются `stickers/stub-*.png` (маркер в имени) и копируются, только если в папке нет ни одной картинки; свои наклейки кладутся рядом, а `stub-*.png` удаляются. `rive/timer.riv` и `carve/pumpkin.glb` необязательны и заглушек не имеют. `head.riv`-заглушка — текстовый файл, ТВ при этом рисует голову на CSS.
8. **Голова на этапе 1** — CSS-заглушка с кнопкой «Позвать сейчас» (без таймера). Факт отмечается показанным по команде `head_shown` от ТВ. Таймер, Rive, липсинк и «Озвучить» — модуль 04.
9. **Профиль Firefox** задаётся папкой (`--profile <папка>`), а не именем (`-P pumpkin`): не нужно править `profiles.ini`, работает и со snap-Firefox (папка `~/snap/firefox/common/pumpkin-profile`). В профиль пишется `user.js` с `media.autoplay.default = 0`.
10. **`opencv-python-headless`** вместо `opencv-python`: та же библиотека без GUI-зависимостей (Qt), кадры с вебки снимаются одинаково.
11. **`start.bat` с переводами строк CRLF** (`.gitattributes`): cmd.exe ненадёжно разбирает .bat с LF. Остальные файлы — LF.
12. **Резервные копии:** `data/backups/<ГГГГММДД-ЧЧММСС>/` с `pumpkin.db` (через SQLite backup API) и `files.txt` (список файлов data/ с размерами); последние 12. Ещё одна копия при остановке сервера. Перед сбросом — полная копия `data/` в `backups/before_reset_<ts>/`.
13. **Сброс вечера** требует подтверждения в диалоге и ввода слова «СБРОС»; удаляет игроков, очки, журнал, показанные факты, настройки и папки `avatars/ uploads/ photos/ pumpkins/`.
14. **Время.** Весь серверный код берёт время из `server/clock.py`; `--speed N` ускоряет его для симулятора. Имена резервных копий — по настоящим часам.
15. **Симулятор** по умолчанию поднимает свой сервер на свободном порту с временной папкой данных и перезапускает его посреди прогона; с `--url` работает с внешним сервером (и сначала сбрасывает вечер!). Сценарий `evening` пока проходит только ядро, квиз/игра/резьба добавятся на своих этапах.
16. **Деплой с Windows** (`tools/deploy.ps1`): tar → scp → распаковка, т. к. rsync в Windows обычно нет. Удалённые на ПК файлы на ноутбуке не удаляются (в `deploy.sh` с rsync — удаляются, кроме `data/`).
17. **`quiz.yaml` и `facts.yaml` наружу не отдаются** (в них ответы); по HTTP доступны только `content/images/` и `content/audio/`.
18. **Пример контента** в `content/` помечен «ЧЕРНОВИК-ПРИМЕР», `/check` честно показывает по нему ошибки, пока не будет настоящего.

## Этап 2 (прототип резьбы, модуль 06)

19. **Модель заказчика** («Pumpkin», Batuhan13, CC BY 4.0) упакована в `assets/carve/pumpkin.glb` (`tools/pack_model.py`; 2,8 МБ). Проверено: тело — замкнутая поверхность, развёртка без перекрытий, черенок в отдельной области текстуры. Развёртка **со швами** (≈12 островов) — резке это не мешает (см. п. 21). Без файла работает процедурная тыква. Автор указан на `/carve` и в `docs/CREDITS.md` (требование лицензии).
20. **Полая тыква** = внешняя оболочка модели + внутренняя, сдвинутая на 0,06 радиуса по усреднённым нормалям. Обе режутся одной маской, поэтому в вырезе видна толщина стенки. Нижняя часть черенка, уходящая внутрь тела, скрывается.
21. **Резка — проход в UV-пространстве** (рекомендация спеки). Каждый тексель тела проецируется камерой, с которой сделан разрез; он режется, только если попал в контур, смотрит на камеру (задняя стенка цела) и не закрыт другими частями (буфер глубины; берётся самая дальняя глубина в окрестности 3×3 и допуск по наклону, иначе крутые склоны рёбер «закрывали» сами себя пунктиром). Тексели за краями островов добиваются на 2 пикселя — на швах нет щелей. Маски 2048×2048: R = насквозь, G = декор.
22. **Отмена**: хранится список шагов (контур в долях экрана + угол камеры), отмена = база + повтор шагов. Шаг старше 20-го впекается в базу. Так не нужно держать 20 копий маски в памяти iPad.
23. **Свеча** — свечение внутренней оболочки в шейдере (ярче у пламени), а не точечный источник: без теней он светил бы сквозь стенку на черенок и макушку, и 8 источников в аллее дороже. Декор в темноте светится тёплым.
24. **Управление**: увидев `pointerType === "pen"`, страница включает режим пера (перо режет, пальцы вращают и масштабируют, касания во время пера игнорируются); кнопка «без пера» возвращает переключатель «Вращать / Резать». Второй палец во время штриха пальцем отменяет штрих и превращается в жест камеры. Пока открыт контур лассо, камера заблокирована (иначе контур съедет).
25. **Полигональное лассо**: тап ставит точку, двойной тап или тап по первой точке замыкает, есть кнопка «Замкнуть». Лассо замыкается при отпускании. Вырезает кнопка «Вырезать».
26. **Декор**: три толщины S/M/L (1,2 / 2,4 / 4,5 % высоты экрана), одна глубина, штрих применяется при отпускании. Давление Pencil не используется.
27. **«Спереди»** для снимков = круговое среднее углов камеры по всем шагам резки (откуда в основном резали); третий снимок — поворот на 35°. «Готово» сначала включает предпросмотр в темноте с медленным вращением, «Сохранить» делает снимки 1024×1024 и отправляет всё на сервер.
28. **Черенок не режется** (в спеке не сказано; резать черенок насквозь выглядело бы странно).
29. **Блокировка до голосования**: сервер отказывается сохранять тыкву при настройке `carve_locked`; её включит запуск голосования (день 11).
30. `?fps=1` в адресе `/carve` показывает частоту кадров — для решения «идём / не идём» на iPad.

### Решение «идём / не идём»

**Идём (16.10.2026).** Заказчик проверил прототип на своём iPad (сервер на Windows-ПК в домашней сети) — 3D-резьба остаётся целью, лесенка отступления не нужна. Список, по которому проверяли (`/carve?fps=1`):
- вращение и рисование плавные (30+ к/с), Pencil режет, ладонь не мешает, без Pencil работает переключатель;
- лассо и полигон вырезают только видимую сторону, задняя стенка цела, на швах нет полос;
- декор светлеет и светится при свече, не насквозь;
- отмена 20 шагов, «Заново», свеча; «Готово» → «Сохранить» → повторное открытие возвращает ту же тыкву;
- время одного разреза (на глаз: не должно быть заметной паузы) и нет перезагрузки страницы от нехватки памяти.

## Этап 3 (квиз, модуль 02)

31. **Ход вопроса.** После разбора кнопка «Следующий вопрос» сразу показывает следующий вопрос (отдельное «Показать вопрос» нужно только для первого вопроса раунда). После последнего вопроса та же кнопка открывает «Итоги раунда», оттуда — «Начать раунд N+1». Раунды строго по порядку 1→2→3→4; раунд без вопросов не начинается (раунд 4 — без показанных фактов с `quiz`).
32. **Кто может отвечать**: игроки, вошедшие до показа вопроса (вошедший во время заставки раунда уже участвует). Автозакрытие «через 2 с после последнего»: когда ответили все *подключённые* из них. Отвалился без ответа — не ждём; вернулся без ответа, пока вопрос идёт — снова ждём его.
33. **Порядок прихода** для бонусов = порядковый номер записи ответа в базе (монотонный, не зависит от часов). Метка времени используется только для «за сколько секунд ответил».
34. **Ведущий-игрок** отвечает как все, 200 за верный пишутся в ledger, бонус уходит следующим верным в зачёте; в рейтингах вне зачёта не показывается.
35. **Скрытие общего рейтинга** включается в момент показа итогов раунда 3: на этом экране уже только рейтинг раунда. Переключатель на `/host` по-прежнему работает в любой момент.
36. **Вкладка «Факты»** закрыта с заставки раунда 4 до его итогов; в это время сервер вообще не отдаёт тексты фактов (а не только прячет вкладку).
37. **Раунд 4**: ответ до 200 символов, лишние пробелы схлопываются. Вердикт снимается повторным нажатием; «Остальные отметить ✗» — для всех без вердикта. Пока есть ответы без вердикта, «Раскрыть» неактивна.
38. **Звуки ТВ**: тик `warning-tick.mp3` раз в секунду в последние 10 с, `correct.mp3` при разборе. Вибрация на Android: показ вопроса, начало последних 10 с, конец времени.
39. **Часы при ускорении** (симулятор): после перезапуска время сервера продолжается с максимума из сохранённой отметки и последнего события журнала, иначе ускоренные часы «откатывались» и дедлайны уезжали.
40. **Тестовый контент** для автотестов и симулятора — `tests/fixtures/content` (генерирует `tools/make_test_content.py`); папку контента можно подменить переменной `PUMPKIN_CONTENT`. Настоящий контент в `content/` пока черновик-пример.
## Этапы 4-6 (фото, голова, игра, аллея, финал — модули 03, 04, 05, 06, 07)

41. **Фото на диске** называются случайными именами (`data/photos/<hex>.jpg`), а не номером из базы: файл пишется до записи в базу. Скрытые фото отдаются только с `?all=1` (для `/host`).
42. **Редактор селфи**: снимок уменьшается до 2048 px ещё в браузере; фильтры применяются к картинке в полном разрешении, наклейки ставятся поверх и экспортируются в том же масштабе. Наклейки: перетаскивание, рамка с поворотом и масштабом, щипок двумя пальцами. Отмена — до 30 шагов. Черновик (картинка + фильтр + наклейки) — в IndexedDB, переживает смену сцены и перезагрузку. Три кнопки: «Сделать селфи» (фронталка), «Основная камера», «Из галереи». HEIC, который браузер не открывает (Android), переводит сервер (`/api/convert_image`). «Поделиться» появится только там, где браузер его разрешает (на HTTP — обычно нет).
43. **Случайный кадр вебки**: срок 8-15 минут; если наступил в другой сцене или пока на экране голова — кадр ждёт разрешённого момента. Ручная кнопка «Сделать кадр» снимает сразу. Переключатель «Случайные кадры вебки» на `/host`. Карточка нового селфи не показывается, пока на экране голова (так в спеке).
44. **Финальное фото**: обрезка по центру до 4:3 и для вертикального снимка (страница ведущего предупреждает «переверни телефон»); результат на ТВ показывается, если снят после включения сцены.
45. **Скачивание**: несколько фото — ZIP собирается во временный файл `data/tmp/` и удаляется после отдачи. Тыквы в ZIP идут тремя снимками каждая. «Моя» тыква определяется по токену из `localStorage` телефона.
46. **Голова**: следующее появление считается от прошлого показа; смена интервала на `/host` пересчитывает срок. Rive подключается, только если `head.riv` не заглушка; wasm Rive — локальный (по умолчанию runtime качает его с CDN, это переопределено). Липсинк: `tools/make_lipsync.py` читает mp3 через `soundfile` (без ffmpeg).
47. **Игра**: расписание строится от «приземлений»: 34 хороших предмета (30 по 10 и 4 золотых по 50 = 500) с зазором не меньше 0,45 с, гнилые — в промежутках не ближе 0,3 с к хорошим; со временем падения быстрее и чаще. Играют те, кто в сети на старте. Счёт сервер пересчитывает сам по номерам пойманных (телефон присылает только их). Результат принимается до конца + 5 с (обрыв связи: телефон дошлёт после возврата). Тренировку можно повторять, зачёт — один раз; «Сбросить игру» удаляет очки за игру.
48. **Голосование**: тыквы без голосов не получают места и бонуса (иначе при нуле голосов все были бы «первыми»). Раскрытие — от последнего места к первому, тыквы без мест первыми; после последней — общая таблица, и на странице скачивания появляется раздел «Тыквы». Анонимность: игроки получают снимки по номеру (`/media/vote/<n>/…`); прямые адреса `/media/pumpkins/<id>/…` остаются (резьбе на iPad они нужны) — подобрать их вручную теоретически можно.
49. **Аллея**: маски тыкв для показа — 1024×1024 (вместо 2048 на iPad), чтобы 8 тыкв помещались в память ноутбука; свеча у каждой мерцает со своей фазой, сверху «лунный» свет. Порог запасного режима 24 к/с — константа на ТВ (как в config по умолчанию).
50. **Общий рейтинг**: места считаются при входе в сцену (до первого раскрытия), «↺ Начать заново» пересчитывает. После раскрытия первого места общий рейтинг перестаёт быть скрытым — телефоны снова показывают суммы. Разбивка: квиз (с бонусами), игра, резьба и «прочее» (ручные правки), если они не нулевые.
51. **Таймер**: по нулю — сигнал `game-end.mp3` и «Время вышло!». Своё значение — в минутах (дробные можно). «+1 минута» работает и на паузе.
52. **Сцена `download`**: телефоны показывают крупную кнопку «Скачать фото вечера» (не перекидывают на страницу сами — чтобы не терять приложение, если ведущий переключит сцену дальше).
53. **Симулятор `evening`** проходит весь вечер: ядро, квиз, игра (обрыв посреди), резьба (5 тыкв, голосование, независимый пересчёт мест), таймер, рейтинг, финальное фото, ZIP — и сверяет итоговые очки каждого игрока.
## Исправления по ревью (код и архитектура)

54. **Вне зачёта и резьба**: тыква ведущего стоит в аллее и собирает голоса, но в места и бонусы не входит (SPEC 7). Новые суммы после закрытия голосования телефоны получают только после раскрытия итогов на ТВ.
55. **Повтор начислений**: закрытие голосования и финиш игры сначала удаляют свои записи в ledger — повтор после сбоя не удваивает очки. «Сбросить голосование за резьбу» (аварийное) отменяет бонусы и снимает блокировку тыкв.
56. **Игра после перезагрузки или фона**: упавшие за время отсутствия предметы считаются пропущенными (раньше сверялись с корзиной в центре — «фантомные» очки).
57. **Сохранение тыквы**: файлы пишутся во временную папку, подмена и проверка блокировки — в одном шаге в цикле событий; занятые файлы на Windows дают понятную ошибку «нажмите ещё раз».
58. **Супервизор**: `start.sh` перезапускает упавший сервер через 2 с; `tools/remote.sh restart` просто убивает процесс (поднимет супервизор), `stop` кладёт `data/.stop`.
59. **ТВ при переподключении** не пересоздаёт сцену (видео, аллея и звуки не перезапускаются), а обновляет состояние. Аллея меряет частоту кадров только после 5 с прогрева; ведущий может принудительно включить слайды («Аллея на ТВ» в разделе сцены).
60. **config.yaml**: `game.practice_seconds/scored_seconds`, `carve.fps_fallback_threshold`, `slideshow.seconds_per_photo`, `ambient.new_photo_card_seconds` теперь действуют.
61. **Регистр имён файлов** контента проверяется даже на Windows (`check_content`), id фактов всегда строки. Синтаксис всех клиентских JS проверяет `tools/check_js.mjs` (и тест, если есть node).
62. **Зависимости закреплены** точными версиями в `requirements.txt`.
63. **Титры**: `content/credits.txt` показывается внизу `/download` (атрибуция CC BY/BY-SA фото сортов и 3D-модели).
