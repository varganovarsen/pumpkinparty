# Решения по ходу работы

Мелкие детали, которых нет в спеке (SPEC 0). Заказчик просматривает.

## Этап 1 (ядро)

1. **Вход и загрузка фото через REST, остальное через WebSocket.** Загрузка файлов по WS неудобна; `join`/`claim` идут через `POST`, чтобы получить токен до открытия WS. Все прочие изменения — команды по WS.
2. **Фото-профиль: обрезка на телефоне, обработка на сервере.** Телефон отправляет оригинал, сервер делает HEIC→JPEG и EXIF-поворот и отдаёт превью; на превью гость двигает и масштабирует круг; сервер режет PNG 256×256 с прозрачными углами. Фильтры и наклейки для профиля подключатся вместе с редактором селфи (модуль 03), в спеке они «опционально».
3. **Профиль ведущего:** создаётся по ссылке «Создать мой профиль игрока» на `/host` (открывает `/?as_host=1`). Ведущий может быть только один. `in_scoring` ведущего = `host_in_scoring`; менять нельзя после флага `quiz_started` (выставит модуль 02).
4. **«Это я?»** — по имени без учёта регистра, только если у игрока нет ни одного живого подключения.
5. **Живые сцены** на этапе 1: `quiz`, `game`, `carve_vote` целиком требуют подтверждения при выходе. Модули 02/05/06 сузят это до живой фазы.
6. **«Следующий шаг»** = следующая сцена по рекомендуемому порядку (SPEC 8): ambient → квиз → перерыв → игра → аллея → итоги резьбы → рейтинг → финальное фото → слайд-шоу → скачивание. Модули будут подставлять контекстные шаги (например «Показать вопрос»).
7. **Заглушки ассетов.** Эталоны лежат в `server/stubs/` (генерирует `tools/make_stubs.py`, нужен ffmpeg). Сервер при старте копирует заглушку на место отсутствующего файла в `assets/`. Файл считается заглушкой, пока его хэш совпадает с эталоном, — замена файлом с тем же именем работает без правок кода. Наклейки-заглушки называются `stickers/stub-*.png` (маркер в имени) и копируются, только если в папке нет ни одной картинки; свои наклейки кладутся рядом, а `stub-*.png` удаляются. `rive/timer.riv` и `carve/pumpkin.glb` необязательны и заглушек не имеют. `head.riv`-заглушка — текстовый файл, ТВ при этом рисует голову на CSS.
8. **Голова на этапе 1** — CSS-заглушка с кнопкой «Позвать сейчас» (без таймера). Факт отмечается показанным по команде `head_shown` от ТВ. Таймер, Rive, липсинк и «Озвучить» — модуль 04.
9. **Профиль Firefox** задаётся папкой (`--profile <папка>`), а не именем (`-P pumpkin`): не нужно править `profiles.ini`, работает и со snap-Firefox (папка `~/snap/firefox/common/pumpkin-profile`). В профиль пишется `user.js` с `media.autoplay.default = 0`.
10. **`opencv-python-headless`** вместо `opencv-python`: та же библиотека без GUI-зависимостей (Qt), кадры с вебки снимаются одинаково.
11. **`start.bat` с переводами строк CRLF** (`.gitattributes`): cmd.exe ненадёжно разбирает .bat с LF. Остальные файлы — LF.
12. **Резервные копии:** `data/backups/<ГГГГММДД-ЧЧММСС>/` с `pumpkin.db` (через SQLite backup API) и `files.txt` (список файлов data/ с размерами); последние 12. Ещё одна копия при остановке сервера. Перед сбросом — полная копия `data/` в `backups/before_reset_<ts>/`.
13. **Сброс вечера** требует подтверждения в диалоге и ввода слова «СБРОС»; удаляет игроков, очки, журнал, показанные факты, настройки и папки `avatars/ uploads/ photos/ pumpkins/`.
14. **Время.** Весь серверный код берёт время из `server/clock.py`; `--speed N` ускоряет его для симулятора. Имена резервных копий — по настоящим часам.
15. **Симулятор** по умолчанию поднимает свой сервер на свободном порту с временной папкой данных и перезапускает его посреди прогона; с `--url` работает с внешним сервером (и сначала сбрасывает вечер!). Сценарий `evening` пока проходит только ядро, квиз/игра/резьба добавятся на своих этапах.
16. **Деплой с Windows** (`tools/deploy.ps1`): tar → scp → распаковка, т. к. rsync в Windows обычно нет. Удалённые на ПК файлы на ноутбуке не удаляются (в `deploy.sh` с rsync — удаляются, кроме `data/`).
17. **`quiz.yaml` и `facts.yaml` наружу не отдаются** (в них ответы); по HTTP доступны только `content/images/` и `content/audio/`.
18. **Пример контента** в `content/` помечен «ЧЕРНОВИК-ПРИМЕР», `/check` честно показывает по нему ошибки, пока не будет настоящего.

## Этап 2 (прототип резьбы, модуль 06)

19. **Модель заказчика** («Pumpkin», Batuhan13, CC BY 4.0) упакована в `assets/carve/pumpkin.glb` (`tools/pack_model.py`; 2,8 МБ). Проверено: тело — замкнутая поверхность, развёртка без перекрытий, черенок в отдельной области текстуры. Развёртка **со швами** (≈12 островов) — резке это не мешает (см. п. 21). Без файла работает процедурная тыква. Автор указан на `/carve` и в `docs/CREDITS.md` (требование лицензии).
20. **Полая тыква** = внешняя оболочка модели + внутренняя, сдвинутая на 0,06 радиуса по усреднённым нормалям. Обе режутся одной маской, поэтому в вырезе видна толщина стенки. Нижняя часть черенка, уходящая внутрь тела, скрывается.
21. **Резка — проход в UV-пространстве** (рекомендация спеки). Каждый тексель тела проецируется камерой, с которой сделан разрез; он режется, только если попал в контур, смотрит на камеру (задняя стенка цела) и не закрыт другими частями (буфер глубины; берётся самая дальняя глубина в окрестности 3×3 и допуск по наклону, иначе крутые склоны рёбер «закрывали» сами себя пунктиром). Тексели за краями островов добиваются на 2 пикселя — на швах нет щелей. Маски 2048×2048: R = насквозь, G = декор.
22. **Отмена**: хранится список шагов (контур в долях экрана + угол камеры), отмена = база + повтор шагов. Шаг старше 20-го впекается в базу. Так не нужно держать 20 копий маски в памяти iPad.
23. **Свеча** — свечение внутренней оболочки в шейдере (ярче у пламени), а не точечный источник: без теней он светил бы сквозь стенку на черенок и макушку, и 8 источников в аллее дороже. Декор в темноте светится тёплым.
24. **Управление**: увидев `pointerType === "pen"`, страница включает режим пера (перо режет, пальцы вращают и масштабируют, касания во время пера игнорируются); кнопка «без пера» возвращает переключатель «Вращать / Резать». Второй палец во время штриха пальцем отменяет штрих и превращается в жест камеры. Пока открыт контур лассо, камера заблокирована (иначе контур съедет).
25. **Полигональное лассо**: тап ставит точку, двойной тап или тап по первой точке замыкает, есть кнопка «Замкнуть». Лассо замыкается при отпускании. Вырезает кнопка «Вырезать».
26. **Декор**: три толщины S/M/L (1,2 / 2,4 / 4,5 % высоты экрана), одна глубина, штрих применяется при отпускании. Давление Pencil не используется.
27. **«Спереди»** для снимков = круговое среднее углов камеры по всем шагам резки (откуда в основном резали); третий снимок — поворот на 35°. «Готово» сначала включает предпросмотр в темноте с медленным вращением, «Сохранить» делает снимки 1024×1024 и отправляет всё на сервер.
28. **Черенок не режется** (в спеке не сказано; резать черенок насквозь выглядело бы странно).
29. **Блокировка до голосования**: сервер отказывается сохранять тыкву при настройке `carve_locked`; её включит запуск голосования (день 11).
30. `?fps=1` в адресе `/carve` показывает частоту кадров — для решения «идём / не идём» на iPad.

### Решение «идём / не идём»

**Идём (16.10.2026).** Заказчик проверил прототип на своём iPad (сервер на Windows-ПК в домашней сети) — 3D-резьба остаётся целью, лесенка отступления не нужна. Список, по которому проверяли (`/carve?fps=1`):
- вращение и рисование плавные (30+ к/с), Pencil режет, ладонь не мешает, без Pencil работает переключатель;
- лассо и полигон вырезают только видимую сторону, задняя стенка цела, на швах нет полос;
- декор светлеет и светится при свече, не насквозь;
- отмена 20 шагов, «Заново», свеча; «Готово» → «Сохранить» → повторное открытие возвращает ту же тыкву;
- время одного разреза (на глаз: не должно быть заметной паузы) и нет перезагрузки страницы от нехватки памяти.
