# Тыквенный спас — главная спецификация

Версия 1 · 15.10.2026 · документ для Claude Code

## 0. Как работать с этой спекой

- Сначала читай этот файл, затем модульный файл текущего этапа (`MODULE-*.md`). При противоречии главным считается этот файл.
- Работай строго по этапам из раздела 14. Этап заканчивается прогоном чек-листа приёмки из модульного файла и (когда он уже есть) прогоном симулятора.
- Не добавляй функций, которых нет в спеке. Мелкие детали, которых в спеке нет, выбирай самым простым способом и записывай в `docs/DECISIONS.md` (что решил и почему).
- Пометка **[по умолчанию]** означает: решение не обсуждалось с заказчиком, выбрано как разумное. Заказчик такие места просмотрит.
- Заказчик сам делает всю графику, анимацию (Rive), звуки и озвучку. Для каждого такого файла нужна заглушка с тем же именем (раздел 12). Подмена заглушки настоящим файлом не должна требовать правок кода.
- Язык интерфейса: русский. Код и идентификаторы: английский.

## 1. Что строим

Локальное веб-приложение для домашней вечеринки «Тыквенный спас» на 8 человек. Один сервер на ноутбуке с Linux, картинка идёт на телевизор, гости участвуют со смартфонов по домашнему wifi (без установки приложений). Ведущий один, управляет вечером со своего телефона.

Состав вечера: квиз из 4 раундов, мини-игра с падающими тыквами, резьба 3D-тыквы на iPad с голосованием, селфи с фильтрами и наклейками, общий альбом, случайные кадры с вебки, голова-тыква с фактами (Rive), таймер перерывов, слайд-шоу, финальное фото, скачивание фото по QR.

## 2. Окружение

| Что | Решение |
|---|---|
| Сервер и экран телевизора | Ноутбук, Ubuntu (последняя), Firefox в киоск-режиме, HDMI на телевизор |
| Разработка | Windows-ПК, на нём работает Claude Code |
| Связь ПК и ноутбука | ssh (ключи без пароля настраивает заказчик) |
| Телефоны гостей | iPhone и Android, любой современный браузер, подключение по QR |
| Телефон ведущего | iPhone, Chrome (движок WebKit, правила Safari) |
| iPad | Страница резьбы `/carve`, Apple Pencil у ведущего, у гостей можно пальцем |
| Сеть | Домашний роутер, IP ноутбука закреплён по MAC-адресу, интернет не обязателен |
| Вебка | Подключена к ноутбуку, кадры снимает сервер (OpenCV, `/dev/video0`) |

Всё приложение работает по обычному HTTP. HTTPS, WebRTC и живое видео в проект не входят.

Следствия HTTP для iOS (учитывать в коде): нет `getUserMedia`, нет Screen Wake Lock, нет Clipboard API. Камера телефона открывается через `<input type="file" accept="image/*" capture>`. Экраны не гаснут за счёт настроек устройств (чек-лист в `MODULE-08-tooling.md`).

## 3. Жёсткие принципы

1. **Офлайн.** Никаких CDN, внешних шрифтов и скриптов. Все библиотеки лежат в `web/vendor/`.
2. **Без сборки фронтенда.** Чистый JavaScript ES-модулями, без npm, Node и бандлеров.
3. **Сервер главный.** Всё состояние и время хранит сервер. Клиенты это тонкие представления. Время приёма ответа определяется по приходу на сервер.
4. **Всё сохраняется на диск** после каждого события (SQLite и папки с файлами). Перезапуск сервера не теряет вечер.
5. **Кроссплатформенность Windows ↔ Linux.** Пути через `pathlib`, всё в UTF-8, переводы строк LF, имена файлов в нижнем регистре и без пробелов (на Linux регистр важен). Запуск: `start.sh` и `start.bat`.
6. **Заглушки.** Любого файла, который заказчик ещё не прислал, не должно быть причиной ошибки.
7. **Устойчивость.** Телефон, потерявший сеть, и телевизор, перезагрузивший страницу, должны сами вернуться в текущее состояние.

## 4. Стек

- **Сервер:** Python 3.11+, FastAPI, WebSocket (`websockets`/Starlette), SQLite (`sqlite3` или SQLAlchemy на усмотрение).
- **Обработка:** Pillow, `pillow-heif` (HEIC с iPhone), OpenCV (`opencv-python`, вебка), `qrcode`, `numpy` и `scipy` (скрипт липсинка).
- **Клиент:** ES-модули, локально: Rive runtime (+ wasm), Konva (редактор селфи), Three.js (резьба).
- **Конфиг:** `config.yaml` (раздел 13).

## 6. Страницы и доступ

| Адрес | Кто | Доступ |
|---|---|---|
| `/tv` | экран телевизора | только с самого ноутбука (localhost) |
| `/host` | ведущий, мобильная страница | открыта, **без PIN**; ссылок на неё нигде нет (ни в QR, ни на экранах) |
| `/check` | проверки перед вечером | часть `/host` |
| `/` | игрок: вход, профиль, вкладки, сцены | открыта, подключение по QR |
| `/carve` | iPad: резьба | открыта |
| `/download` | скачивание фото | открыта, QR показывается в финале |

Сервер слушает только локальную сеть (в интернет не пробрасывается, порт открыть в `ufw` при необходимости).

## 7. Игроки и профили

- Вход по QR с экрана `/tv` (QR есть и в углу ambient; под QR текстом `http://<ip>:<port>` на случай, если QR не читается).
- Гость вводит имя (уникальное, дубль вежливо отклоняется) и выбирает профиль:
  - тыква-аватар из 8 готовых,
  - или фото: снимок камерой или файл из галереи, затем круглая обрезка (можно фильтр и наклейки через тот же редактор), сохраняется 256×256.
- Сервер выдаёт токен, клиент хранит его в `localStorage`. Перезагрузка страницы и потеря сети возвращают того же игрока.
- Ведущий тоже игрок со своей отдельной вкладкой. Профиль помечен «ведущий», по умолчанию **вне зачёта** (переключатель `host_in_scoring` на `/host`, менять можно до начала квиза). Вне зачёта значит: не попадает в рейтинги и в тройку бонусов, очки записываются, но скрыты.
- Опоздавший подключается в любой момент. В идущей сцене он зритель и участвует со следующего вопроса или следующей сцены; за пропущенное получает 0.

## 8. Сцены и ход вечера

Телевизор показывает ровно одну сцену. Переключает только ведущий (кроме случаев, указанных в модулях).

| Сцена | Описание | Модуль |
|---|---|---|
| `ambient` | фон-видео, QR в углу, голова-тыква, карточки новых фото | 04 |
| `quiz` | раунды вопросов | 02 |
| `game` | падающие тыквы | 05 |
| `timer` | обратный отсчёт перерыва | 07 |
| `carve_vote` | аллея тыкв и голосование | 06 |
| `carve_reveal` | раскрытие авторов, голосов, бонусов | 06 |
| `rating_reveal` | общий рейтинг по одному от последнего места | 07 |
| `final_photo` | «Все в кадр!» и результат | 03 |
| `slideshow` | слайд-шоу всех видимых фото | 07 |
| `download` | QR на страницу скачивания | 07 |

Рекомендуемый порядок вечера (подсказка на `/host`, жёсткого порядка нет):
1. `ambient` почти весь вечер (голова, селфи, альбом, резьба на iPad идут параллельно).
2. Квиз: раунды 1, 2, 3, между ними перерывы (`timer`), в один из перерывов `game`.
3. Раунд 4 (факты, ручная проверка).
4. Финал: `carve_vote` → `carve_reveal` → `rating_reveal` → `final_photo` → `slideshow` → `download`.

Резьба на iPad (`/carve`) доступна всё время, независимо от сцены.

## 9. Очки

Все начисления идут через журнал начислений (ledger), итог всегда считается из журнала. Это позволяет ведущему вручную править очки.

| Источник | Правило | Максимум |
|---|---|---|
| Квиз, правильный ответ | 200, не зависит от времени; неверный 0, без штрафа | 200 за вопрос |
| Квиз, бонус за скорость | первые три **правильных** по времени прихода на сервер: +50, +25, +10 | +50 за вопрос |
| Квиз всего | раунды 1-3 по 10 вопросов, раунд 4 пять вопросов, всего 35 | 8 750 теоретически |
| Игра с падающими тыквами | очки = собранный счёт игры (раздел модуля 05), без нормализации и «победителя» | 500 |
| Резьба, голосование | 1 место 500, 2 место 300, 3 место 100 | 500 |
| **Теоретический максимум вечера** | | **9 750** |

Реально лидер наберёт 5-6 тысяч. Цифры подогнаны под «красивые», не менять без согласования.

Ничьи: одинаковая сумма значит одинаковое место; на экране раскрытия такие игроки показываются вместе, порядок внутри пары случайный.

Ручная правка очков игрока с `/host` пишет запись `manual` в журнал (с комментарием).

## 10. Модель данных (минимум)

- **Player:** id, token, name, avatar_kind (`pumpkin`|`photo`), avatar_ref, is_host, in_scoring, connected, created_at.
- **Ledger:** id, player_id, source (`quiz`|`quiz_bonus`|`game`|`carve`|`manual`), ref, amount, note, ts.
- **Fact:** id, shown_at (null пока голова не показала на телевизоре).
- **QuizSession:** текущий раунд и вопрос, фаза, время старта вопроса, ответы (player, answer, server_ts, seq, verdict для раунда 4).
- **GameRun:** режим (`practice`|`scored`), seed, старт, результаты по игрокам.
- **Photo:** id, kind (`selfie`|`webcam`|`final`), author_id (null у webcam/final), path, thumb, hidden, deleted, created_at.
- **Pumpkin:** player_id, версия, пути к текстурам (`through`, `depth`), снимки, угол камеры, updated_at.
- **Vote:** voter_id, pumpkin_player_id.
- **EventLog:** ts, text (читаемые строки для `/host`, например «Аня ответила на вопрос 3 за 7 с»).
- **Setting:** key, value (режим головы, скрытие общего рейтинга, `host_in_scoring`, лёгкий фон и т. д.).

## 11. Протокол (верхний уровень)

- Один WebSocket на клиента: `/ws?role=tv|host|player|carve&token=…`. Сообщения JSON `{"t": "<type>", …}`.
- При подключении сервер шлёт полный снимок состояния для роли, затем события. Клиент после обрыва переподключается сам и получает снимок заново (повторная доставка должна быть безопасной).
- Клиенты шлют **команды** (`cmd`), сервер проверяет роль и фазу и отвечает событиями. Клиент никогда не меняет состояние сам.
- Синхронизация часов: клиент при подключении измеряет смещение относительно сервера (несколько пингов). Все дедлайны сервер присылает как серверное время; клиенты показывают обратный отсчёт с учётом смещения.
- Порядок ответов в квизе определяется порядковым номером прихода на сервер (при равных метках).
- Список типов сообщений Claude Code проектирует сам и фиксирует в `docs/PROTOCOL.md` до начала этапа 2.

## 12. Ассеты и заглушки

Все пути относительно `assets/`. Заказчик подменяет файл с тем же именем. Страница `/check` показывает, какие файлы всё ещё заглушки (по маркеру в имени или хэшу).

| Файл | Что это | Кто делает |
|---|---|---|
| `rive/head.riv` | голова-тыква, state machine `HeadSM` (раздел модуля 04) | заказчик |
| `rive/timer.riv` | декор таймера (необязателен, контракт согласуется позже) | заказчик |
| `video/ambient.webm` | фон: камин или листопад, WebM VP9, 1080p, 30 к/с, без звука, 4-6 Мбит/с | заказчик |
| `img/ambient-light.jpg` | статичный фон для лёгкого режима | заказчик |
| `overlay/final-frame.png` | рамка и подпись для финального фото, альбомная 4:3, 3000×2250, PNG с прозрачностью, текст внутри | заказчик |
| `avatars/pumpkin-1.png … pumpkin-8.png` | аватары-тыквы | заказчик |
| `stickers/*.png` | 10-12 наклеек для редактора | заказчик |
| `game/pumpkin.png`, `golden.png`, `rotten.png`, `basket.png` | спрайты игры | заказчик |
| `carve/pumpkin.glb` | модель тыквы (необязательна; по умолчанию процедурная модель) | заказчик |
| `sfx/fact-notify.mp3`, `shutter.mp3`, `countdown.mp3`, `correct.mp3`, `wrong.mp3`, `warning-tick.mp3`, `game-*.mp3` | звуки | заказчик |

Контент (факты, вопросы, фото сортов) лежит в `content/` (см. `CONTENT-FORMAT.md`) и пишется отдельно. Озвучка фактов: `content/audio/fact_<id>.mp3`, сервис синтеза выберем позже, формат только mp3.

Заглушки генерирует сервер или скрипт (цветные плейсхолдеры, короткий тон вместо звуков, простая рамка с текстом «Тыквенный спас 2026» для финального фото).

Порядок урезания, если отстаём (сверху вниз, резьба первой):
1. Резьба (лесенка: 3D → плоская тыква с теми же ножами → убрать; без резьбы нет аллеи, голосования и бонуса, максимум очков 9 250).
2. Карточка новых фото в ambient.
3. Случайные кадры вебки.
4. Разбивка очков по категориям в финале.
5. Липсинк по JSON (рот движется по простому циклу).
6. Игра с падающими тыквами.

Не режутся: ядро, квиз, голова с фактами, финальное фото.
