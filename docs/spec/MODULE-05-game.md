# Модуль 05. Игра с падающими тыквами

Этап: день 11. Зависимости: модуль 01. Читать вместе с `SPEC.md` раздел 9.

## Суть

Каждый играет на своём телефоне, на телевизоре общий живой рейтинг. Все играют одновременно, с одинаковым расписанием падений. Победителя нет, каждый получает очки за собственный счёт.

## Управление и предметы

- Корзина внизу экрана, двигается перетаскиванием пальца по горизонтали (корзина следует за пальцем), играть можно одной рукой. Спрайты: `assets/game/pumpkin.png`, `golden.png`, `rotten.png`, `basket.png` (заглушки есть).
- Предметы: обычная тыква **+10**, золотая **+50** (падает реже и быстрее), гнилая **−30**. Счёт игры не опускается ниже 0. Жизней нет, промахи не штрафуются.
- Со временем скорость и частота падений растут.

## Фазы

1. **Тренировка (15 секунд).** Отдельная кнопка «Тренировка» на `/host`, свой seed, в зачёт не идёт. Запускается до зачётной попытки.
2. **Зачёт (45 секунд).** Кнопка «Старт» на `/host`. Одна попытка на игрока.

Запуск синхронный: сервер присылает серверное время старта, на телефонах отсчёт 3-2-1, игра начинается одновременно (с учётом смещения часов клиента, SPEC раздел 11).

## Расписание падений (seed)

- Сервер генерирует детерминированное расписание `(t, x, kind, speed)` по seed и отправляет его всем клиентам одинаковым. Игра клиента симулируется локально по этому расписанию (детерминизм обязателен).
- Расписание зачётной попытки спроектировано так, чтобы **идеальная игра давала ровно 500 очков**: например 30 обычных (300) + 4 золотых (200) собираемых при полном охвате, плюс гнилые, которых нужно избегать. Расписание проверяется тестом: сумма собираемых хороших предметов равна 500, и существует траектория корзины, собирающая их все (скорость корзины не ограничена, но предметы не падают одновременно за пределами досягаемости).
- Расписание тренировки: свой seed, меньше предметов (например 8 обычных, 1 золотая, 3 гнилых).

## Результат и очки

- По окончании клиент отправляет итоговый счёт и список подобранных предметов. Сервер принимает счёт, ограничивая сверху расчётным максимумом 500 [по умолчанию доверяем клиенту, приватная вечеринка].
- Очки в ledger: `min(max(0, score), 500)`, источник `game`. Без нормализации и без распределения по местам.
- Не подключённые на старте и опоздавшие: 0, остаются зрителями.
- Повторить зачёт нельзя (кнопка «Сбросить игру» на `/host` для аварии, пишет в журнал).

## Телевизор

- Живой рейтинг: аватар, имя, текущий счёт, обновление примерно раз в секунду, сортировка по счёту. Отсчёт 3-2-1 крупно, таймер игры.
- В конце: итоговая таблица. Rive-оформление необязательно (заказчик подключит позже).

## Приёмка

- [ ] Тренировка не влияет на очки; зачёт даёт ровно собранный счёт, максимум 500.
- [ ] Старт синхронный на 8 телефонах (расхождение до ~150 мс).
- [ ] Расписание детерминировано: два клиента с одним seed видят одинаковые падения.
- [ ] Тест расписания: идеальная игра = 500.
- [ ] Гнилые вычитают, счёт не уходит ниже 0.
- [ ] Живой рейтинг на `/tv` обновляется во время игры.
- [ ] Обрыв связи посреди игры не ломает сервер; результат отправляется при возврате, если игра ещё идёт, иначе 0.
- [ ] Симулятор прогоняет игру с 8 виртуальными игроками (модуль 08).
